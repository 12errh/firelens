# Roadmap — from prototype to production

Snapshot: 14 Nov 2026 · Frontend: https://firelens-chi.vercel.app · API: https://firelens-api.vercel.app
Status legend: `[x]` done · `[~]` in progress · `[ ]` not started

---

## Where we are

The prototype is deployed and judge-ready:

- 24 PSI investigations, 22 experimental tables, 2,870 normalized rows, 109 document records.
- Dashboard, investigation explorer, investigation detail, oxygen × gravity evidence map,
  assistant, methodology page.
- Deterministic assistant, optional Groq lane, numeric guard, RAG proxy stub.
- FastAPI read-only mirror on Vercel.
- Static snapshot in `web/data/`, generated by `ingest/build_dataset.py`.

What is still metadata-only: **document full text**. There are no chunks, embeddings,
vector search, reranking, or citation-backed document answers yet.

---

## Phase 1 — Real RAG vertical slice (P0)

Goal: prove retrieval quality on a small, high-value subset before scaling.

- [ ] Pick the 10 most relevant reports (BASS-II, FLEX, SAFFIRE-I/II/III, CFI-G, SAME).
- [ ] Resolve PSI download URLs from the file tree; store `sourceUrl`, MIME type, SHA-256.
- [ ] Download and extract text with `pypdf`/`pdfplumber`; OCR fallback for scans.
- [ ] Section-aware chunking (~500–800 tokens, 15% overlap), page + section metadata.
- [ ] Embed with `BAAI/bge-small-en-v1.5`; store model name, dimension, snapshot ID.
- [ ] Build hybrid retrieval: keyword/BM25 + cosine, reciprocal-rank fusion.
- [ ] Add top-k reranking (cross-encoder or hosted reranker).
- [ ] Generate cited answers: `[1]` → `{documentId, page, section, url}`.
- [ ] Extend the numeric guard to numbers found in retrieved text.
- [ ] Create a 20-question golden set with expected pages and required facts.
- [ ] Measure hit@k, citation validity, refusal correctness, latency.

**Acceptance:** 20/20 golden questions retrieve the expected document; every factual
sentence carries a valid citation; unsupported questions are refused.

- [ ] Chunk + embedding artifact versioned by snapshot hash.
- [ ] Hybrid retrieval with metadata filters (accession, gravity, phase, vehicle, year).
- [ ] Streaming answers (SSE) in the chat UI.
- [ ] Retrieval trace: "6 chunks from 3 documents" with expandable sources.
- [ ] Source drawer / PDF viewer at the cited page.
- [ ] Answer cache keyed by question + snapshot + model.
- [ ] Feedback capture (thumbs + reason) stored for eval growth.
- [ ] Golden set expanded to 40–60 questions; eval runs in CI.

**Acceptance:** answer latency p95 < 8 s; citation validity > 95%; zero numeric guard
violations in the eval set; eval results published on `/methodology`.

## Phase 4 — Operations, data, security (P1)

- [ ] JSON schema validation for every generated artifact; fail builds on drift.
- [ ] Snapshot ID + content hash + changelog in the manifest and UI footer.
- [ ] Scheduled refresh via GitHub Actions; artifacts committed, never long-running jobs.
- [ ] Link integrity check for PSI URLs and DOIs.
- [ ] License registry enforced at ingestion.
- [ ] Data dictionary: every field, unit, and null rule.
- [ ] Distributed rate limiting (Upstash Redis) for `/api/chat`.
- [ ] Security headers: CSP, HSTS, nosniff, referrer policy.
- [ ] Prompt-injection defense: retrieved text is data, never instructions.
- [ ] Markdown allowlist rendering; no raw HTML from model output.
- [ ] Dependency scanning, Dependabot, pinned Python deps.
- [ ] Runbook: rollback, re-ingest, rotate keys, restore snapshot.
- [ ] Rotate the Render API key shared during setup (unused, but exposed).

**Acceptance:** CI blocks schema drift and failed evals; no secret in the repo; documented
rollback and re-ingest paths.

## Architecture decisions

1. **Snapshot in git, not a database (for now).** The corpus is small and reproducibility
   matters more than write throughput. Postgres is the Phase 5 upgrade.
2. **Two retrieval lanes.** Tables answer numbers; documents answer interpretation. Tables win
   on conflict.
3. **Bundled vectors before a vector DB.** 109 documents fit in a JSON artifact and keep
   Vercel deploys simple.
4. **Deterministic fallback is a feature, not a failure mode.** The site must answer with no
   API keys and no network model.
5. **The gap is the finding.** No partial-gravity combustion data exists in PSI; the product
   must never blur that into a lunar/Mars prediction.
6. **SI is disclosed everywhere.** Code, copy, assistant, and deck.

## Risks

- PSI document URLs may change or require session handling.
- Scanned PDFs may need OCR; table extraction from PDFs can be lossy.
- Groq model availability can change; keep the fallback and pin the model env.
- Serverless cold starts affect the first assistant request.
- The Render key was exposed in chat and should be revoked.
